Unreleased
==========

Add new changes here as you develop features. When you release, this file will be renamed to the version number (e.g. `0.1.0b3.txt`) and a new `Unreleased.txt` created.

Structure your notes by section: Breaking, Added, Changed, Fixed, Deprecated, Removed, Security.

Each notable change should be a paragraph or bullet, explaining what changed and why — the audience is users upgrading to this version.

Every release carries a `Breaking` heading, including a pre-release. If nothing broke, write "None." under it explicitly — an absent heading reads as "nobody checked", not as "safe to skip".

Breaking
--------

Ten entries from the second round of production field reports and the quality work behind them. Each is a deliberate change of
something that was silently wrong; each comes with a one-line way back.

* **``snapadmin.E027`` can stop ``manage.py check``.** It fires when ``SnapModel``'s own
  ``objects = EsManager()`` silently replaces a manager a mixin declares (``class
  Order(SnapModel, OwnerScopedMixin)`` — Django resolves a manager name by first match in MRO
  order), or when a ``tenant_scoped`` model's ``objects`` is anything but an ``EsManager``, which is
  where tenant isolation is enforced. Both are cross-scope data leaks that nothing reported before.
  Fix: declare a manager inheriting from both on the model (``class OrderManager(OwnerScopedManager,
  EsManager): pass``). If the plain ``EsManager`` really is meant on a model that is not
  tenant-scoped, add ``'snapadmin.E027'`` to ``SILENCED_SYSTEM_CHECKS``.
* **The ``APIToken`` admin is no longer registered while no API accepts tokens.** With both
  ``SNAPADMIN_REST_API_ENABLED`` and ``SNAPADMIN_GRAPHQL_ENABLED`` off, ``register_all_admins()``
  used to offer a screen for minting credentials to a surface that does not exist. A project that
  authenticates its own views with ``APITokenAuthentication`` sets
  ``SNAPADMIN_TOKEN_ADMIN_ENABLED = True`` to keep it.
* **The changelist hides a non-integer primary key.** A UUID ``id`` column was forced first into
  every generated changelist; it is now shown for integer keys only. ``admin_list_display_pk =
  True`` on the model brings it back. A key not named ``id`` used to produce a column that did not
  exist; it is now referenced by its real name.
* **An unmapped REST action is refused.** ``TokenModelPermission`` used to give any viewset action
  missing from its map the ``view`` floor — so a write action added later, and not mapped, would
  have been reachable with read-only rights. ``count``/``export``/``fetch_by``/``OPTIONS`` are now
  mapped to ``view`` explicitly and anything else is denied, superusers included. A project that
  added its own action to a subclassed ``DynamicModelViewSet`` maps it with
  ``SNAPADMIN_API_ACTION_PERMISSIONS = {"my_action": "view"}``. ``@snap_action`` is unaffected.
* **An ``ES_ONLY`` retention purge that fails now raises ``SnapPurgeError``** instead of returning
  ``0``. The task and the management command already report a raising model under ``errors`` /
  ``ERROR``, so a failed purge stops being reported as a clean one. Code calling
  ``purge_expired()`` directly on an ``ES_ONLY`` model should expect the exception.
* **``EsQuerySet.delete()`` on an ``ES_ONLY`` model raises ``SnapEsUnavailable`` when
  Elasticsearch cannot delete** instead of counting the documents as deleted. A GDPR subject-access
  erasure (``snapadmin_subject_request delete``) used to print "Deleted N row(s)" after such a
  failure; it now stops with the error. Code calling ``delete()`` on an ES search result directly
  should expect the exception.
* **The SFTP location in the backup summary and in ``db_backup_stored`` is the directory the server
  resolved**, not the configured string. With a relative ``SNAPADMIN_BACKUP_SFTP_DIR`` the reported
  path therefore now starts at the login directory (``sftp://host:22/home/backup/backups/...``
  instead of ``sftp://host:22/backups/...``). Only code that parses that string is affected.
* **CSV exports neutralise spreadsheet formulas.** A text value starting with ``=``, ``+``, ``-``,
  ``@``, a tab or a carriage return is written behind a leading ``'`` in ``export_format="csv"`` and
  in ``snapadmin_audit_export --format csv`` (see Security). A program that reads those files and
  needs the raw text either strips one leading ``'`` from such cells or switches to the JSON format,
  which is unchanged.
* **``snapadmin.E028`` can stop ``manage.py check``.** It fires for a masking setting written in a
  shape it cannot mean — a string or a number where ``SNAPADMIN_MASKED_FIELDS`` expects a list of
  field names, a list where ``SNAPADMIN_MASKING_RULES`` expects a field → rule map, or either
  setting not being a dict at all. Such a setting used to mask nothing (or crash every masked
  request and the check run itself). Fix: write it in the documented shape.
* **``POST /api/exports/`` refuses ``filters`` that are not a JSON object of scalars** with a
  ``400`` naming the key, and reports every ``filters`` error — including the key allowlist, which
  used ``non_field_errors`` — under ``filters``. A client that read the allowlist error from
  ``non_field_errors`` reads it from ``filters`` instead. ``__in`` now takes a list; a string there
  used to match its individual characters.

Added
-----

* **Restore drills — ``snapadmin_restore --database <alias>``.** Restores the ``db`` part into
  another ``DATABASES`` alias and leaves ``default`` untouched, then prints the row count of every
  table; a restore that produced no tables fails instead of reporting success. An alias that
  resolves to the same database as ``default`` is refused, ``media``/``env`` cannot be sent there
  (they would land on the live system), and on PostgreSQL the drill database is emptied by
  recreating its ``public`` schema, so the drill role needs no ``CREATEDB``. Public helpers
  ``snapadmin.restore.table_row_counts()`` and ``verify_restored_database()`` expose the same check.
* **``SNAPADMIN_PURGE_EXTERNAL = True``** declares that an external scheduler (cron, a Kubernetes
  CronJob) runs ``manage.py snapadmin_purge_expired_data``, so ``snapadmin.W012`` stops asking for a
  Celery Beat entry. Before, following the warning's own advice kept the warning forever.
* **Renaming an API token** — ``PATCH /api/tokens/<id>/`` with ``{"token_name": "…"}``, for the
  owner or a superuser, audited. Any other field in the body is a ``400`` naming it: scope and
  expiry are fixed at creation, and a change to them means a new token.
* **``SNAPADMIN_TOKEN_ADMIN_ENABLED``** — see Breaking.
* **``SNAPADMIN_API_ACTION_PERMISSIONS``** — see Breaking.
* **The test suite ships in the sdist** (never the wheel), with the demo project, docs and
  ``pytest.ini`` it runs against: unpack the source distribution and run ``python -m pytest``
  inside to hold an installed version to the checks CI runs. Verified: the full suite passes from
  an unpacked sdist.
* **``snapadmin-new --admin-only``** generates the admin alone — no REST API or GraphQL apps, both
  switches off, a base-install ``requirements.txt``, and a ``--full`` health check that does not
  depend on the API. The default project still serves all three surfaces (token-authenticated,
  permission-gated), since showing them from one model is what the generator is for.
* **The demo project wires a restore drill** (``RESTORE_DRILL_DB_NAME`` adds a ``restore_drill``
  alias) and shows ``admin_list_display_pk = False`` on its ``Tag`` model.
* **``admin_list_display_pk``** on ``SnapModel`` — see Breaking.
* **Snap fields accept a positional ``verbose_name``**, like every Django field:
  ``SnapCharField("Label", max_length=200)`` used to raise a ``TypeError`` that named neither the
  argument nor the fix, on every field of a model being moved onto Snap fields.
* **New system checks** for configurations that looked complete and silently did nothing:
  ``snapadmin.W023`` (backups configured — a ``snapadmin.run_db_backups`` Beat entry, a destination
  or AGE recipients — while ``SNAPADMIN_BACKUP_ENABLED`` is off, so every run stores nothing),
  ``snapadmin.W024`` (``env`` in ``SNAPADMIN_BACKUP_INCLUDE`` with no file behind
  ``SNAPADMIN_BACKUP_ENV_FILE``), ``snapadmin.W025`` (a model with masked fields served by a
  hand-written ``ModelAdmin`` without ``PIIMaskingAdminMixin``, which shows them raw), and
  ``snapadmin.E027`` (see Breaking).
* **``SnapPurgeResult``** — what ``SnapModel.purge_expired()`` now returns: still an ``int`` (the
  purged count), with a ``skipped_protected`` attribute. Existing callers are unaffected.

Changed
-------

* **``llms.txt`` is now an operating manual, not only a docs map.** Both copies (the repository root,
  shipped in the sdist, and ``docs/llms.txt``, published at ``/llms.txt``) carry four new layers for an
  assistant helping someone run SnapAdmin in production: the *Decisions to settle with the developer*
  interview grew from 12 questions to 18 — the load profile the project must carry, ``AUTH_USER_MODEL``
  and whether the login is an e-mail or a username, what guards the login door (SnapAdmin ships no SSO,
  no second factor and no login throttling of its own), how the application reaches the database and as
  whom, what the audit trail records and what it silently does not (admin writes, not REST/GraphQL
  writes or ``QuerySet.update()``), and where a failure becomes visible — followed by a *Build order for
  a new project*, a *Testing a project built on SnapAdmin* checklist, a *Production readiness and high
  load* section that states the shipped defaults (page size 25 capped at 500, 60/min and 600/min
  throttles, the 100 000-row estimated-count threshold, the JSON-filter scan cap, the export chunk
  size), and *Development norms in a SnapAdmin project*. No behaviour changed; what changed is how much
  a model has to infer. The same material is now on the documentation site as a **Production Playbook**
  section (``#playbook``), linked from the README, so the human-facing and the machine-facing copies say
  the same thing.

* **Short values are masked harder.** An e-mail whose local part is one or two characters masks to
  ``***@domain`` — ``a***@x.io`` for ``a@x.io`` printed the whole local part. A
  ``SNAPADMIN_MASKING_RULES`` ``pattern`` that matches nothing in a non-empty value falls back to
  the built-in masker instead of returning the value unchanged.

* **``snapadmin.W022``'s hint names both SFTP cases.** On several managed SFTP products the login
  directory *is* the absolute path; dropping the leading slash, as the hint used to advise, created
  a same-named directory inside it and put every dump one level too deep, with a success report
  either way. The hint now says when to keep the absolute form, the reported location is the
  directory the server resolved, and a directory created on the fly is logged as the warning
  ``sftp_backup_dir_created``.

* **Query counts are pinned on the N+1-prone surfaces.** ``tests/test_query_counts.py`` drives the
  changelist with foreign keys and a many-to-many, the REST list endpoint, the audit timeline and
  the masked changelist/list/timeline through real HTTP requests and counts their SQL twice — at 3
  rows and at 12. The two numbers must match (a per-row query anywhere makes them differ) and the
  larger one is pinned exactly, so a new query on a hot path has to be a decision rather than an
  accident. None of the surfaces had an N+1 today; the pins keep it that way.

* **Property-based and fuzz tests.** ``hypothesis`` (a dev dependency only — it never reaches
  ``pip install django-snapadmin``) now checks laws over generated input rather than a handful of
  examples: ``decrypt(encrypt(x)) == x`` for any text and any keyset, a field rebuilt from its own
  ``deconstruct()`` deconstructs identically for any combination of kwargs, a DSN never leaks any
  part of its password, a masked character class never survives its rule, CSV and NDJSON exports
  round-trip, and hostile REST query strings, export filters, masking settings, key configurations
  and HTML are refused correctly. 100 examples per test locally, 300 in CI. The first pass found the
  defects listed under Security and Fixed.

* **The type check is blocking.** ``mypy`` ran on every push but reported rather than failed,
  because 136 findings sat in the dynamic admin and field layers. They are gone, so a type error
  now fails CI. Most of them were one shape: a mixin that calls ``super().handle_exception()`` or
  reads ``self._meta`` has no base class saying those exist, so the call was never checked at all.
  Each mixin now declares what it is mixed into in an ``if TYPE_CHECKING:`` block — the DRF view or
  serializer it extends, or the attributes a ``SnapModel`` supplies — which changes nothing at
  runtime. ``encryption/``, ``crypto.py``, ``sharding/``, ``backup.py``, ``validators.py``,
  ``logging_config.py`` and ``quickstart/`` additionally run under raised strictness: every function
  annotated, every untyped body checked. Two public signatures are now honest about accepting
  ``None`` (``SnapFileValidator``'s three upload limits, ``SnapStatusBadgeField``'s ``verbose_name``
  and ``style_arguments``) — a documentation fix, not a behaviour change.

* **Mutation testing, advisory.** ``mutmut`` now answers the question coverage cannot: would a test
  *notice* the code being wrong? One command runs it — ``python scripts/mutation.py diff`` mutates
  only the functions a change touched (minutes, and what CI runs on every push), ``python
  scripts/mutation.py modules`` mutates the encryption, crypto, sharding-router, masking, API-filter,
  backup, restore and task modules whole (what CI runs weekly). Both **report and never block**: a
  surviving mutant is either killed by a stronger test or accepted in writing, and an equivalent
  mutant cannot be killed at all. The mechanism — what gets mutated, how the diff scoping picks it,
  what "survived" means and what to do about one — is documented in ``CONTRIBUTING.md`` and in the
  docs site's Testing section.

Fixed
-----

* **A single ``PROTECT``-ed row no longer stops a model's retention purge.** One due row still
  referenced through a ``PROTECT``/``RESTRICT`` foreign key (a tree whose parent is due before its
  children) made the single bulk delete raise, so nothing was purged for that model, run after run
  — and the ``data_retention_files`` pass had already deleted the files of every due row, leaving
  rows that point at files that no longer exist. Protected rows are now kept and retried on the next
  run, a fully due subtree goes leaves first, files go only with rows actually deleted, and the kept
  rows are reported: ``SnapPurgeResult.skipped_protected``, a ``SKIPPED`` line in
  ``snapadmin_purge_expired_data``, and a ``skipped_protected`` map in the Celery task's summary.
* **Deleting an Elasticsearch search result of a ``DUAL`` model deletes the rows.** ``snap_search``
  / ``es_search`` return an ``EsQuerySet`` for ``DUAL`` models too; its ``delete()`` used to remove
  nothing and report every row as deleted. It now deletes them from the database (the mirror is
  cleared by the existing ``post_delete`` receiver) and returns Django's own counts.
* **``snapadmin_restore`` and ``take_snapshot`` refuse a part they cannot handle** instead of
  skipping it — ``perform_restore`` used to log such a part as applied.
* **``send_error_digest`` / ``send_health_alert`` always return a ``status``.** An unrecognised
  reason used to fall through and return ``None``, invisible to a ``status != "ok"`` monitoring
  rule; it is now a ``partial`` naming the reason.
* **Swallowed exceptions are logged.** Four ``except: pass`` sites (the dashboard's model counts and
  Elasticsearch ping, the diagnostics token count, Django's inline history entry) now log what they
  swallowed, so a failure there is diagnosable instead of invisible.
* **PII masking and ``api_field_permissions`` no longer switch off on a hand-built serializer.**
  ``PIIMaskingSerializerMixin`` and ``FieldPermissionSerializerMixin`` read the model only from the
  ``_snap_model`` attribute SnapAdmin sets on the serializers it generates; a project's own
  ``ModelSerializer`` mixing them in never had it, and the mixins then returned every field raw —
  behind a coverage pragma that called the path unreachable. They now fall back to ``Meta.model``.
* **``delete_pks_from_es()`` reports a partial failure.** A ``delete_by_query`` answer carrying a
  ``failures`` list now returns ``False`` (so ``DUAL`` purges raise ``SnapPurgeError``) instead of
  counting as a cleared mirror.
* **A masked changelist column keeps the field's ``verbose_name``**, translation included, instead
  of a title-cased field name.
* **Generated ``ModelAdmin`` classes report the model's module as ``__module__``**, not a
  ``django.forms`` internal — tracebacks and "is this admin generated?" tests now name the right
  place.
* **The demo project schedules its backup task only while backups are on**, so it no longer
  exhibits the very state ``snapadmin.W023`` reports.
* **``snap_field()`` no longer rewrites a field's migration state through ``editable``.** Passing
  ``editable=`` to the wrapper as well as ``editable=False`` to the Django field removed the
  constructor's own ``editable=False`` from ``deconstruct()``, so ``makemigrations`` wrote an
  ``AlterField``; and ``editable=True`` on a wrapped ``auto_now``/``auto_now_add`` field made
  Django's own ``deconstruct()`` raise ``KeyError`` — ``makemigrations`` crashed. The wrapper now
  reports exactly what the Django constructor was given, and keeps an ``auto_now`` field read-only
  the way Django and ``Snap*Field`` already do.
* **Configuring an encryption key as bytes or a number is a configuration error** naming the key
  id, not an ``AttributeError`` out of configuration loading.
* **The ``SnapField`` docstring and ``llms.txt`` state the second migration exception**: on
  ``SnapFileField``/``SnapImageField`` the upload limits are recorded in ``deconstruct()`` the way
  Django records ``validators=``, so changing one is an ``AlterField`` that runs no SQL.

Security
--------

Found by the new static-analysis pass (Ruff's bandit rules), each fixed with a regression test:

* **``formatted_id`` escaped a non-integer primary key into the changelist as markup.** A
  character primary key is data — possibly user-supplied — and was rendered through
  ``mark_safe``, a stored-XSS path for any changelist using that column. It is now escaped.
* **Alert webhooks refuse any scheme but ``http``/``https``.** ``urllib`` would otherwise also follow
  ``file:``, ``ftp:`` or a custom handler for a misconfigured ``SNAPADMIN_ALERT_WEBHOOKS`` entry.
* **``snapadmin_restore`` quotes the database name in the SQL it sends to ``psql``.** A name
  containing a quote produced invalid (or different) SQL; it is now escaped as an SQL literal.

Found by the new property-based and fuzz tests, each fixed with a regression test:

* **CSV exports never open as spreadsheet formulas (CWE-1236).** The XLSX writer already pinned a
  ``=``-cell to text; the CSV writer wrote ``=HYPERLINK(…)`` raw, and so did
  ``snapadmin_audit_export``, whose ``user_agent`` column is whatever the client sent. Text cells
  opening with ``= + - @``, a tab or a carriage return now carry a leading ``'``.
* **No part of a sharding DSN's password reaches an error message.** A generated password with a
  raw ``/``, ``#`` or ``?`` ended the URL's authority early: ``redact_dsn`` found no password and
  echoed the whole DSN into ``ImproperlyConfigured`` (and so into ``manage.py check`` and the logs),
  and the port error quoted the password's first half. A digits-only password followed by ``/``
  even parsed — into the wrong host, with no password. Redaction now works on the text as written,
  and an ``@`` after the host is refused with a percent-encoding hint.
* **A masking setting in the wrong shape no longer fails open.** ``"email"`` instead of
  ``["email"]`` masked the fields ``e``, ``m``, ``a``… (none of them real); it now masks ``email``.
  A list of names under ``SNAPADMIN_MASKING_RULES`` masks those fields with the built-in masker
  instead of crashing. ``snapadmin.E028`` reports both (see Breaking).
* **Export ``filters`` are validated by shape before the allowlist runs.** A JSON list passed the
  key allowlist (its elements were read as keys) and a list of numbers answered ``500``.

Deprecated
----------

* **``SnapModel.admin_sections``** has never been read by any code path. Setting it now raises
  ``snapadmin.W026``; it will be removed in a future release. Group form fields with the per-field
  ``tab`` and ``row`` flags, or pass ``fieldsets`` through ``admin_overrides``.
